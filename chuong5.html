Chương 5: Hàm trong C++

5.1. Tổng quan về hàm

5.1.1. Vì sao cần hàm?

Trong các chương trước, chương trình của chúng ta thường được viết toàn bộ bên trong main(). Cách viết này chỉ phù hợp với các bài toán nhỏ. Khi chương trình lớn dần (hàng trăm, hàng nghìn dòng), việc dồn tất cả vào main() gây ra nhiều vấn đề:

  • Khó đọc: một khối lệnh khổng lồ, không biết đâu là phần nào.
  • Khó bảo trì: sửa một chỗ có thể ảnh hưởng nhiều nơi khác.
  • Lặp code: cùng một đoạn xử lý phải copy–paste nhiều lần.
  • Không tái sử dụng được cho chương trình khác.

Hàm (function) ra đời để giải quyết những vấn đề trên. Hàm cho phép gom một nhóm câu lệnh thực hiện một nhiệm vụ cụ thể thành một khối có tên, và gọi lại nhiều lần ở bất kỳ đâu trong chương trình.

Ví dụ thực tế:

  • Tính căn bậc hai → gọi sqrt(x) có sẵn, không cần viết lại thuật toán.
  • Kiểm tra số nguyên tố → viết một lần, gọi nhiều lần cho các số khác nhau.
  • In menu chương trình → viết hàm inMenu(), gọi mỗi khi cần.

5.1.2. Khái niệm hàm

Hàm là một khối lệnh có tên, nhận dữ liệu đầu vào (tham số), thực hiện một công việc, và có thể trả về một giá trị cho nơi gọi.

// Ví dụ: hàm tính tổng hai số nguyên
int tong(int a, int b) {
    return a + b;
}

// Gọi hàm trong main
int main() {
    int kq = tong(3, 5);     // kq = 8
    return 0;
}

5.1.3. Lợi ích của hàm

  • Tái sử dụng mã (reusability): viết một lần, dùng nhiều lần.
  • Chia để trị (divide and conquer): chia bài toán lớn thành nhiều bài nhỏ dễ giải quyết.
  • Dễ đọc: tên hàm mô tả công việc, code gọn gàng hơn.
  • Dễ gỡ lỗi (debug): lỗi khu trú trong một hàm, dễ tìm và sửa.
  • Tránh lặp code (DRY – Don't Repeat Yourself): một đoạn logic chỉ viết một chỗ.
  • Dễ mở rộng: thêm chức năng mới chỉ cần thêm hàm, không đụng code cũ.

5.1.4. Vị trí của hàm trong chương trình

Một chương trình C++ điển hình có cấu trúc:

    #include ...
    using namespace std;

    // Khai báo (prototype) — nếu cần
    int ham1(int a);
    void ham2();

    // Hàm main — điểm bắt đầu chương trình
    int main() {
        // gọi các hàm
        return 0;
    }

    // Định nghĩa các hàm khác
    int ham1(int a) { ... }
    void ham2() { ... }

Trong C++, hàm có thể được định nghĩa trước hoặc sau main():

  • Nếu định nghĩa trước main() → không cần khai báo prototype.
  • Nếu định nghĩa sau main() → bắt buộc phải có prototype ở phía trên.

5.2. Cấu trúc của một hàm

5.2.1. Cú pháp

kieu_tra_ve ten_ham(danh_sach_tham_so) {
    // thân hàm
    return gia_tri;   // nếu kiểu trả về khác void
}

Trong đó:

  • kieu_tra_ve: kiểu dữ liệu hàm trả về (int, double, bool, void, …)
  • ten_ham: tên hàm, đặt theo quy tắc định danh (chữ cái, chữ số, dấu _, không bắt đầu bằng số)
  • danh_sach_tham_so: các tham số đầu vào, cách nhau bởi dấu ,; có thể rỗng
  • return: trả kết quả về cho nơi gọi — bắt buộc với hàm không phải void

5.2.2. Các thành phần chi tiết

    int          tong       (int a, int b)    { return a + b; }
     │            │                │                  │
     │            │                │                  └── thân hàm
     │            │                └── danh sách tham số
     │            └── tên hàm
     └── kiểu trả về

5.2.3. Ví dụ cơ bản

Ví dụ 1: Hàm không trả về giá trị (void).

#include <iostream>
using namespace std;

void xinChao() {
    cout << "Hello World!" << endl;
}

int main() {
    xinChao();     // In: Hello World!
    xinChao();     // In: Hello World!
    return 0;
}

Ví dụ 2: Hàm có trả về giá trị.

double dienTichHinhTron(double r) {
    return 3.14159 * r * r;
}

int main() {
    double s = dienTichHinhTron(2.0);
    cout << "Dien tich: " << s << endl;
    return 0;
}

Ví dụ 3: Hàm có nhiều tham số.

int tinhTong(int a, int b, int c) {
    return a + b + c;
}

int main() {
    cout << tinhTong(1, 2, 3) << endl;   // 6
    return 0;
}

5.2.4. Phân loại hàm theo kiểu trả về

  • Hàm void: không trả về giá trị — dùng để in, nhập, thay đổi dữ liệu qua tham chiếu.
  • Hàm có trả về: trả về một giá trị cụ thể — dùng để tính toán, kiểm tra, tìm kiếm.

Lưu ý: Với hàm không phải void, mọi nhánh của hàm (kể cả trong if…else) đều phải có return. Nếu thiếu, chương trình có thể trả về giá trị rác.

// SAI — có nhánh không return
int kiemTra(int x) {
    if (x > 0) return 1;
    // thiếu return khi x <= 0
}

// ĐÚNG
int kiemTra(int x) {
    if (x > 0) return 1;
    return 0;
}

5.3. Khai báo hàm (Function Prototype)

5.3.1. Khái niệm

Khai báo hàm (prototype) là dòng khai báo tên hàm, kiểu trả về, và danh sách kiểu tham số — nhưng không có thân hàm. Prototype giúp trình biên dịch biết trước "sẽ có một hàm như vậy" để kiểm tra cú pháp khi gọi hàm trước khi định nghĩa.

5.3.2. Cú pháp

kieu_tra_ve ten_ham(kieu_tham_so_1, kieu_tham_so_2, ...);

Chú ý: Prototype kết thúc bằng dấu ; và không có thân hàm.

5.3.3. Ví dụ

#include <iostream>
using namespace std;

// Prototype — khai báo trước
int tong(int a, int b);
double dienTich(double r);

int main() {
    cout << tong(3, 5) << endl;       // 8
    cout << dienTich(2.0) << endl;    // 12.5664
    return 0;
}

// Định nghĩa hàm — sau main
int tong(int a, int b) {
    return a + b;
}

double dienTich(double r) {
    return 3.14159 * r * r;
}

5.3.4. Lưu ý quan trọng

  • Tên tham số trong prototype có thể bỏ qua — chỉ cần kiểu dữ liệu: 
    int tong(int, int);   // Hợp lệ
  • Prototype phải khớp với định nghĩa hàm về kiểu trả về và kiểu tham số.
  • Nếu hàm chỉ dùng trong một file, có thể định nghĩa trước main() để khỏi cần prototype.

5.4. Truyền tham số cho hàm

C++ cung cấp ba cách truyền tham số cho hàm. Việc chọn đúng cách rất quan trọng vì nó ảnh hưởng đến việc hàm có thể thay đổi biến gốc hay không.

5.4.1. Truyền theo giá trị (Pass by Value) — mặc định

Hàm nhận một bản sao của biến. Thay đổi trong hàm không ảnh hưởng đến biến gốc bên ngoài.

void tang(int x) {
    x = x + 1;    // chỉ thay đổi bản sao
    cout << "Trong ham: x = " << x << endl;   // 6
}

int main() {
    int a = 5;
    tang(a);
    cout << "Trong main: a = " << a << endl;   // 5
    return 0;
}

Ưu điểm: an toàn — hàm không thể vô tình làm hỏng dữ liệu gốc.
Nhược điểm: tốn thời gian sao chép nếu dữ liệu lớn (struct, mảng lớn, string dài).

5.4.2. Truyền theo tham chiếu (Pass by Reference) — dùng &

Hàm nhận chính biến gốc (không sao chép). Thay đổi trong hàm ảnh hưởng trực tiếp đến biến gốc.

void tang(int &x) {     // dấu & biểu thị tham chiếu
    x = x + 1;          // sửa trực tiếp biến gốc
}

int main() {
    int a = 5;
    tang(a);
    cout << a << endl;   // 6
    return 0;
}

Ưu điểm: không sao chép — nhanh với dữ liệu lớn; cho phép hàm trả về nhiều giá trị qua tham số.
Nhược điểm: cần cẩn thận, tránh sửa ngoài ý muốn. Nếu không muốn thay đổi, dùng const &.

5.4.3. Truyền theo con trỏ (Pass by Pointer) — dùng *

Hàm nhận địa chỉ của biến. Truy cập và thay đổi giá trị gốc thông qua toán tử giải tham chiếu *.

void tang(int *x) {
    (*x)++;              // tăng giá trị tại địa chỉ x trỏ tới
}

int main() {
    int a = 5;
    tang(&a);            // truyền địa chỉ của a
    cout << a << endl;   // 6
    return 0;
}

Ưu điểm: có thể truyền nullptr để biểu thị "không có giá trị".
Nhược điểm: cú pháp phức tạp hơn, dễ nhầm với tham chiếu. Ít dùng trong code hiện đại, trừ khi cần tương tác mảng động, cấu trúc dữ liệu, API C.

5.4.4. So sánh ba cách truyền

+-------------------+-------------+---------------------+-----------------+
|     Cách truyền   |  Cú pháp    |  Ảnh hưởng gốc?     |  Sao chép?      |
+-------------------+-------------+---------------------+-----------------+
|  Theo giá trị     |  int x      |  Không              |  Có             |
|  Theo tham chiếu  |  int &x     |  Có                 |  Không          |
|  Theo con trỏ     |  int *x     |  Có (qua *x)        |  Chỉ địa chỉ    |
+-------------------+-------------+---------------------+-----------------+

Khuyến nghị:

  • Dùng truyền theo giá trị khi hàm không cần thay đổi biến gốc và dữ liệu nhỏ (int, double, char, bool).
  • Dùng truyền theo tham chiếu khi cần thay đổi biến gốc, hoặc khi dữ liệu lớn (dùng const & nếu không sửa).
  • Hạn chế dùng con trỏ trừ khi có lý do đặc biệt.

5.5. Tham số mặc định (Default Arguments)

5.5.1. Khái niệm

Có thể gán giá trị mặc định cho tham số trong prototype/định nghĩa hàm. Khi gọi hàm mà không truyền đối số đó, hàm sẽ dùng giá trị mặc định.

5.5.2. Cú pháp

kieu_tra_ve ten_ham(tham_so_1, tham_so_2 = gia_tri_mac_dinh);

5.5.3. Ví dụ

double dienTich(int dai, int rong = 5) {
    return dai * rong;
}

int main() {
    cout << dienTich(4) << endl;        // 20 (dùng rong = 5)
    cout << dienTich(4, 3) << endl;     // 12 (ghi đè mặc định)
    return 0;
}

5.5.4. Quy tắc vàng

  • Tham số có giá trị mặc định phải nằm bên phải các tham số không mặc định. 
    // ĐÚNG
void f(int a, int b = 0, int c = 1);

// SAI — b có mặc định nhưng c thì không
void f(int a, int b = 0, int c);    // LỖI biên dịch
  • Không nên lạm dụng — dễ gây nhầm lẫn khi có nhiều tham số mặc định.
  • Giá trị mặc định phải là hằng số biểu thức (literal, const, …), không phải biến.

5.6. Nạp chồng hàm (Function Overloading)

5.6.1. Khái niệm

Nạp chồng hàm cho phép nhiều hàm cùng tên nhưng khác danh sách tham số (khác số lượng hoặc khác kiểu). Trình biên dịch sẽ chọn hàm phù hợp dựa trên các đối số được truyền vào.

5.6.2. Ví dụ

#include <iostream>
using namespace std;

int tong(int a, int b) {
    return a + b;
}

double tong(double a, double b) {
    return a + b;
}

int tong(int a, int b, int c) {
    return a + b + c;
}

int main() {
    cout << tong(2, 3) << endl;           // 5   → bản int 2 tham số
    cout << tong(2.5, 3.1) << endl;       // 5.6 → bản double
    cout << tong(1, 2, 3) << endl;        // 6   → bản 3 tham số
    return 0;
}

5.6.3. Quy tắc nạp chồng

  • Hàm phải khác nhau về danh sách tham số: khác số lượng, khác kiểu, hoặc khác thứ tự kiểu.
  • KHÔNG thể nạp chồng chỉ dựa vào kiểu trả về: 
    // LỖI
int    f(int x);
double f(int x);    // trùng tham số → lỗi biên dịch
  • Nạp chồng không phân biệt tham chiếu và giá trị (nếu chỉ khác &): 
    // LỖI — trình biên dịch không phân biệt được
int f(int x);
int f(int &x);
  • Cẩn thận khi có tham số mặc định và nạp chồng cùng lúc — có thể gây nhập nhằng (ambiguity).

5.7. Hàm đệ quy (Recursion)

5.7.1. Khái niệm

Đệ quy là kỹ thuật hàm gọi lại chính nó. Đây là cách tiếp cận tự nhiên cho các bài toán có cấu trúc lặp đi lặp lại với quy mô nhỏ dần (chia để trị, duyệt cây, hoán vị, …).

5.7.2. Cấu trúc của hàm đệ quy

Một hàm đệ quy bắt buộc phải có:

  1. Điều kiện dừng (base case): trường hợp đơn giản nhất, trả về kết quả trực tiếp mà không gọi lại chính nó.
  2. Bước đệ quy (recursive case): gọi lại chính hàm với bài toán nhỏ hơn.

Nếu thiếu điều kiện dừng → gọi mãi mãi → tràn stack (stack overflow).

5.7.3. Ví dụ

Ví dụ 1: Giai thừa n!.

long long giaiThua(int n) {
    if (n == 0 || n == 1) return 1;    // điều kiện dừng
    return n * giaiThua(n - 1);         // bước đệ quy
}

Minh họa: giaiThua(4) = 4 * giaiThua(3) = 4 * 3 * giaiThua(2) = … = 4 * 3 * 2 * 1 = 24.

Ví dụ 2: Số Fibonacci thứ n.

int fibo(int n) {
    if (n <= 1) return n;               // điều kiện dừng
    return fibo(n - 1) + fibo(n - 2);   // bước đệ quy
}

Ví dụ 3: UCLN — thuật toán Euclid.

int ucln(int a, int b) {
    if (b == 0) return a;               // điều kiện dừng
    return ucln(b, a % b);              // bước đệ quy
}

Ví dụ 4: Đếm số chữ số của n.

int demChuSo(int n) {
    if (n < 10) return 1;               // điều kiện dừng
    return 1 + demChuSo(n / 10);        // bước đệ quy
}

5.7.4. Ưu và nhược điểm của đệ quy

+---------------------------+----------------------------------+
|        Ưu điểm            |         Nhược điểm               |
+---------------------------+----------------------------------+
| Code ngắn gọn, dễ hiểu    | Tốn bộ nhớ stack mỗi lần gọi     |
| Tự nhiên với bài đệ quy   | Chậm hơn vòng lặp (do overhead)  |
| (cây, đồ thị, hoán vị)    | Dễ tràn stack nếu đệ quy sâu     |
| Dễ chứng minh tính đúng   | Có thể tính lại nhiều lần        |
+---------------------------+----------------------------------+

Khuyến nghị: dùng đệ quy khi bài toán có cấu trúc đệ quy tự nhiên, độ sâu nhỏ (≤ vài nghìn). Với bài toán đơn giản lặp lại nhiều lần (như Fibonacci), dùng vòng lặp hoặc quy hoạch động sẽ hiệu quả hơn.

5.8. Biến toàn cục, cục bộ và static

5.8.1. Biến cục bộ (Local Variable)

Khai báo bên trong một hàm (hoặc một khối { }). Chỉ dùng được trong phạm vi đó, và bị hủy khi ra khỏi phạm vi.

void hamA() {
    int x = 10;          // cục bộ trong hamA
    cout << x;           // OK
}

void hamB() {
    // cout << x;        // LỖI — x không tồn tại ở đây
}

5.8.2. Biến toàn cục (Global Variable)

Khai báo ngoài tất cả các hàm. Dùng được ở mọi hàm trong file, tồn tại suốt chương trình, giá trị khởi tạo mặc định là 0.

int count = 0;           // biến toàn cục

void tangCount() {
    count++;             // truy cập trực tiếp
}

int main() {
    tangCount();
    tangCount();
    cout << count << endl;   // 2
    return 0;
}

Cảnh báo: Lạm dụng biến toàn cục khiến chương trình khó hiểu, khó debug (vì bất kỳ hàm nào cũng có thể sửa). Chỉ dùng khi thực sự cần (ví dụ: hằng số cấu hình, cờ trạng thái chung).

5.8.3. Biến static cục bộ

Là biến cục bộ nhưng tồn tại suốt chương trình (không bị hủy khi ra khỏi hàm) và chỉ khởi tạo một lần. Rất hữu ích để đếm số lần gọi hàm, hoặc lưu trạng thái giữa các lần gọi.

void dem() {
    static int x = 0;    // chỉ khởi tạo lần gọi đầu
    x++;
    cout << x << endl;
}

int main() {
    dem();   // 1
    dem();   // 2
    dem();   // 3
    return 0;
}

So sánh:

+------------------+-------------------+----------------------+
|   Loại biến      |  Phạm vi truy cập |  Thời gian tồn tại   |
+------------------+-------------------+----------------------+
|  Cục bộ          |  Trong khối {}    |  Khi khối còn chạy   |
|  Toàn cục        |  Cả file          |  Suốt chương trình   |
|  Static cục bộ   |  Trong khối {}    |  Suốt chương trình   |
+------------------+-------------------+----------------------+

5.9. Phạm vi hàm và từ khóa inline

5.9.1. Phạm vi (Scope)

  • Biến được khai báo trong khối { } chỉ tồn tại trong khối đó.
  • Biến cục bộ che khuất (shadow) biến toàn cục cùng tên trong phạm vi của nó.
  • Toán tử :: (scope resolution) truy cập biến toàn cục khi bị che: 
    int x = 100;            // toàn cục

void f() {
    int x = 5;          // cục bộ, che x toàn cục
    cout << x << endl;   // 5
    cout << ::x << endl;// 100 (toàn cục)
}

5.9.2. Từ khóa inline

inline là gợi ý với trình biên dịch rằng nên "nhúng" code của hàm vào nơi gọi thay vì sinh lệnh gọi hàm. Giúp tăng hiệu năng với các hàm nhỏ, gọi nhiều lần (giảm overhead của lời gọi hàm).

inline int binhPhuong(int x) {
    return x * x;
}

Lưu ý: inline chỉ là gợi ý — trình biên dịch có quyền bỏ qua nếu thấy không hợp lý. Không nên lạm dụng với hàm lớn (làm phình code).

5.10. Hàm main và tham số dòng lệnh

5.10.1. Cú pháp mở rộng của main

Hàm main() có thể nhận hai tham số để đọc dữ liệu từ dòng lệnh:

int main(int argc, char* argv[]) {
    // argc: số lượng tham số (bao gồm tên chương trình)
    // argv: mảng con trỏ, chứa các chuỗi tham số
    return 0;
}

5.10.2. Ví dụ

Chạy chương trình: ./a.out 5 7

#include <iostream>
#include <cstdlib>
using namespace std;

int main(int argc, char* argv[]) {
    if (argc != 3) {
        cout << "Su dung: ./a.out a b" << endl;
        return 1;
    }
    int a = atoi(argv[1]);   // chuyển chuỗi sang số
    int b = atoi(argv[2]);
    cout << "Tong: " << a + b << endl;
    return 0;
}

Kết quả:

    argc = 3
    argv[0] = "./a.out"
    argv[1] = "5"
    argv[2] = "7"
    → In ra: Tong: 12

5.11. Các lỗi thường gặp

  • Quên prototype khi định nghĩa hàm sau main() — chương trình báo lỗi "not declared in this scope". Cách sửa: khai báo prototype trước main().
  • Thiếu return trong hàm có kiểu trả về khác void — chương trình trả về giá trị rác hoặc lỗi.
  • Không có return trong một nhánh của if — tương tự trên, hàm trả về giá trị không xác định.
  • Nhầm lẫn tham chiếu và giá trị — quên dấu & khiến hàm không sửa được biến gốc.
  • Đặt tham số mặc định sai vị trí — void f(int a = 0, int b) là lỗi cú pháp.
  • Nạp chồng chỉ khác kiểu trả về — lỗi biên dịch, không hợp lệ.
  • Đệ quy không có điều kiện dừng — tràn stack, chương trình crash.
  • Quên dấu { } khi thân hàm có nhiều câu lệnh — chỉ câu lệnh đầu tiên thuộc hàm, các câu lệnh sau nằm ngoài (thường trở thành câu lệnh rác trong main).
  • Quên dấu ; sau prototype — lỗi biên dịch.
  • Lạm dụng biến toàn cục — chương trình khó debug khi có lỗi.
  • Nhầm hàm đệ quy với vòng lặp vô hạn — đệ quy luôn cần điều kiện dừng, không có điều kiện dừng thì không khác gì vòng lặp vô hạn.

    long long kq = 1;
    for (int i = 2; i <= n; i++) kq *= i;
    return kq;

// Đệ quy

5.14. Tóm tắt chương

  • Hàm là khối lệnh có tên, thực hiện một nhiệm vụ cụ thể, có thể nhận tham số và trả về giá trị.
  • Lợi ích: tái sử dụng, dễ đọc, dễ bảo trì, dễ gỡ lỗi.
  • Cú pháp: kieu_tra_ve ten_ham(danh_sach_tham_so) { ... return ...; }.
  • Prototype cần có khi hàm được định nghĩa sau main().
  • Truyền theo giá trị: hàm nhận bản sao, không ảnh hưởng biến gốc.
  • Truyền theo tham chiếu (&): hàm nhận biến gốc, thay đổi được.
  • Truyền theo con trỏ (*): hàm nhận địa chỉ, thay đổi được qua *.
  • Tham số mặc định phải nằm bên phải; không nên lạm dụng.
  • Nạp chồng hàm: cùng tên, khác danh sách tham số.
  • Đệ quy: hàm gọi chính nó, cần điều kiện dừng + bước đệ quy.
  • Biến toàn cục dùng được mọi nơi; static cục bộ tồn tại suốt chương trình nhưng chỉ có phạm vi trong hàm.
  • inline gợi ý nhúng code — phù hợp hàm nhỏ, gọi nhiều.
  • Luôn thụt lề đúng, dùng { } ngay cả khi thân hàm ngắn, và return đầy đủ ở mọi nhánh.
